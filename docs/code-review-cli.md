# Code review

`@anureo/code-review` reviews a directory using `@anureo/workflow`. A module
analysis agent inspects the codebase and assigns source files to modules. After
analysis completes, modules run concurrently; each module also runs its review
angles concurrently. The built-in angles are **correctness**, **code quality**,
and **design**, all enabled by default. Correctness looks for reachable behavior
failures; code quality and design can also report concrete maintenance costs
supported by source evidence.

The entire review runs inside `workflow()`. Module analysis is one `run.step()`;
each module/angle pair is another step. Validated plans and findings are saved
before the corresponding step completes, followed by the final report.

## CLI

Requires Bun 1.4.2+ and an installed, authenticated Codex CLI. From this workspace:

```sh
bun run review --help
bun run review packages/workflow
bun run review . --concurrency 8 --focus 'Check session resource cleanup'
bun run review . --model my-model --json > review.json
bun run review . --max-modules 1 --angle correctness
bun run review . --module code-review-workflow --angle design
```

The package also exposes the `anureo-review` executable. The optional directory
defaults to the current directory. `CODEX_BIN` overrides the Codex executable;
`--model` overrides `CODEX_MODEL`, otherwise the backend chooses its default.
Progress goes to stderr and the final text or JSON report goes to stdout.
The CLI sets Codex's read-only permission mode and denies approval requests.
Run IDs and the workflow storage directory are printed to stderr and included in
the report. Storage defaults to `<review-directory>/.anureo/workflows`; override it
with `--workflow-dir <path>`. Each run has a `run.json` manifest, step attempts and
checkpoints, and a final `result.json` when the body finishes successfully.

Exit codes are `0` for a complete review with no findings, `1` for a complete
review with findings, and `2` for invalid inputs, failed analysis, incomplete
reviews, or cleanup errors. A failed module/angle remains in the report and is
never represented as a successful review with no findings. Ordinary review
failures leave the workflow incomplete while siblings continue. Unknown execution
outcomes, session cleanup failures, and workflow storage failures stop new step
dispatch and reject the workflow after active steps settle. The CLI exits with
code `2` in those cases. Agent calls are not retried automatically.

Use `--max-modules 1 --angle correctness` for a small run: one module analysis
agent followed by one correctness review agent. The module limit takes the first
modules in analysis order. Use `--module <id>` to select exact IDs from the current
analysis plan instead; IDs appear in reports. Analysis remains necessary, and IDs
are generated by the analysis agent on each run. An unknown ID fails before any
review agents start and lists the available IDs.

`--angle <id>` accepts `correctness`, `code-quality`, or `design`. Repeat `--module`
or `--angle` to select several. Module selection preserves analysis order; angle
selection preserves argument order. If both `--module` and `--max-modules` are
given, the limit applies after filtering. Invalid angle names and invalid limits
fail before backend initialization. Omitting these options reviews all analyzed
modules with all built-in angles.

Reports retain the full module plan and record the selected IDs in `scope`.
The text report shows how many planned modules were selected. A `completed`
status describes completion of that selected scope; excluded modules have no
review result and are not reported as having no findings.

## Programmatic use

```ts
import { reviewCode, defaultAngles } from '@anureo/code-review'

// client is an initialized SDK Client owned by the caller.
const report = await reviewCode({
  client,
  cwd: process.cwd(),
  concurrency: 8,
  angles: defaultAngles,
  workflowDirectory: '.anureo/workflows',
  onProgress: event => console.error(event),
})
```

The workflow borrows the Client and releases each agent session through
`agent()`. Callers own Client disposal and backend permissions. Review
prompts request read-only analysis; enforcement belongs to the supplied backend.
The Client must support structured output. The CLI uses Codex, while library
callers can supply another compatible Client.

`reviewCode()` returns the report with its `runId` and `workflowDirectory`. Each
invocation creates a new run. Checkpoints currently serve as durable execution
records; cross-run reuse and resume are not exposed because source dependencies
and effective backend configuration are not fully fingerprinted. Step reuse is
explicitly disabled to prevent stale review results.

Add a perspective by passing an `angles` array of `{ id, title, instructions }`
objects. IDs must be unique. Omitting `angles` selects all three built-in angles
in the order above. Import `correctnessAngle`, `codeQualityAngle`, or `designAngle`
to select a built-in subset.
Pass `maxModules: 1` to limit the number of reviews, or `moduleIds: ['module-id']`
to select analyzed modules by exact ID. For example, `angles: [correctnessAngle]`
with `maxModules: 1` runs one review agent after analysis. These selections are
also recorded in the workflow input and persisted report.
A shared `concurrency` limit (default eight) bounds active review agents
across both levels; it does not separately multiply the module and angle limits.
The initial analysis agent finishes before any review begins.

Reports preserve analysis order for modules and input order for angles. Findings
include priority `P0`–`P3`, title, explanation, source path, and a 1-based inclusive
line range. Module files must exist within the selected directory and have a
single owner. Finding locations are checked against those files and their line
counts. Invalid analysis aborts before review; invalid findings fail that angle.
The module plan is agent-generated; these checks validate ownership and locations,
not exhaustive source coverage or the truth of a finding. This version reviews
the current files in a directory, rather than selecting a Git diff.
